# CI 分钟数

私有仓库用托管 CI（例如 GitHub Actions）要算分钟数；Windows、macOS 机器通常按倍数计费。多会话开发推送频繁，最容易在这里超支。

## 先量，再改

- **运行次数和时长**：按事件、分支、结论列出最近的运行，例如 `gh run list --json databaseId,event,headBranch,conclusion,createdAt`。每次运行的时长用它的作业（jobs）的 `started_at` 和 `completed_at` 算，例如 `gh api repos/<owner>/<repo>/actions/runs/<id>/jobs`。旧的 run `timing` 接口 GitHub 已经宣布关闭，不要再用。
- **实际计费**：以平台的用量报告为准（GitHub 在账户设置的 Billing 里），自己算的时长只用来找出大头。
- **中途取消的运行照样计费。** 推得勤的分支，大部分运行会被下一次推送取消，但已经跑掉的时间都算钱。

## 可选的做法（按收益排）

采用任何一条之前，**先核对项目的合并门禁**：草稿 PR、普通 PR、进发布分支的 PR，各自要求哪些检查。在 GitHub 上，按条件被跳过的作业会显示为成功，即使它被设成了必需检查（required check），没跑的验证也可能被放行。跳过某个作业之前，确认门禁不依赖它；或者让门禁看一个「汇总」作业，由它检查必要的作业确实跑过、通过。

1. **一个提交只查一次。** 直接推送只让发布分支（如 `main`）跑；开发分支和集成分支靠它们的 PR 查。否则推一次会 push 和 PR 各跑一遍。
2. **常开的集成 PR 开成草稿，草稿不跑。** 云端会话往常驻分支推得最勤。留一个手动触发（GitHub：`workflow_dispatch`），或者标成 ready 时再跑；进发布分支的 PR 不管是不是草稿都跑。手动跑出的结果，要对得上门禁要求的受检提交和检查名称。

   ```yaml
   on:
     pull_request:
       types: [opened, synchronize, reopened, ready_for_review]
     workflow_dispatch:
   jobs:
     check:
       if: github.event_name != 'pull_request' || github.base_ref == 'main' || !github.event.pull_request.draft
   ```
3. **能在 Linux 上跑的搬到 Linux。** lint、类型检查、大多数单元测试通常不依赖操作系统。想知道哪些测试离不开 Windows，在 WSL 或 Linux 里真跑一遍，比读代码猜准。特定系统的机器只留给真正需要的部分，并按改了哪些目录决定开不开。
4. **按目录跳过。** 只改文档不跑；没改原生代码就跳过原生代码的检查。同样要先核对门禁。
5. **自己的机器当 runner（self-hosted）。** 不花分钟数，缓存一直在，所以更快。代价：关机时 CI 排队；跑的时候占用户的 CPU。**信任边界**：runner 会执行触发它的任何代码。只用于可信的代码：自己的分支、已经审过的改动。未经审查的分支、外部贡献的 PR，在用户日常用的电脑上跑，即使用低权限账户也隔离不了用户的环境；这类代码要么继续用托管 runner，要么用专用的隔离机器。折中办法是只把特定系统的那部分搬过去，而且只给可信分支用。

## 和分工的关系

- **谁触发完整检查，可以和成本挂钩**：频繁推送的一方不每次都触发，由负责合并的一方在合并前触发。前提是门禁允许，见上。
- **CI 不可用**（额度用完、账单停掉）时，在本地跑能跑的检查，分开记录「本地跑过的」和「远端没跑的」。本地结果**不能代替**项目的合并门禁：按项目档案等 CI 恢复，或者走档案里事先定好的替代流程。

## 坑

- GitHub 的 bash 默认带 `pipefail`。`echo "$files" | grep -q x` 在 grep 先退出时，echo 会收到 SIGPIPE，整条命令判为失败。改用 `grep -q x <<< "$files"`。

## Cirra 的数字（2026-11，仅供参考）

- **实测的运行样本**：常开 PR 一天约 35 次运行，其中 23 次中途取消；单元测试在 Windows 托管机器上 3.5 分钟，在 Linux（WSL）上 21 秒。
- **估算**（按改动前两周的节奏外推，没有经过账单核实）：改之前每月约 5000 分钟，改之后约 2000 分钟。
