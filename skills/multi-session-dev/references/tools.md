# 各工具怎么做

正文用的是通用说法：开一个会话、派子代理、开 worktree、发消息。下面写各工具的具体做法。标〔未验证〕的是没有在实际项目里用过的，用之前先在该工具里确认。

| 通用说法 | Claude Code（CLI / 桌面应用） | claude.ai | Codex |
|---|---|---|---|
| 仓库指令文件 | `CLAUDE.md` | 项目说明（Project instructions） | `AGENTS.md`〔未验证细节〕 |
| 开一个开发会话 | CLI：`claude -w <名字>` 或在 worktree 里起 `claude`；桌面应用：管理会话开新会话（可选独立 worktree） | 新对话；碰不到本地仓库，只适合设计和评审 | 新任务〔未验证〕 |
| 派子代理 | 子代理（Agent / Task 工具），只交回摘要，彼此不能通信 | 无 | 〔未验证〕 |
| 开 worktree | 有项目脚本用脚本；否则 `git worktree add ../<repo>-<名字> -b <分支>`。子代理的 `isolation: worktree` 默认从默认分支开，不会接入项目要的本地资源 | 无 | 〔未验证〕 |
| 会话之间发消息 | 桌面应用：会话之间可以互发消息；被开出来的会话结束一轮时，管理会话会收到通知 | 无 | 〔未验证〕 |
| 云端会话 | 云端会话推到远端分支；不会回发消息，要看它的记录或 PR | 无 | 云端任务产出 PR〔未验证〕 |

## Claude Code 的实际经验（Cirra，2026-11）

- **结束通知只显示前几百字。** 管理会话收到的通知会截断，细节得去翻对方的记录，很耗上下文。所以结束报告的第一句一定要把「分支 @ 提交｜状态｜在等谁」写全。
- **权限确认不能转交。** 开发会话被拦下的安装、下载、登录，管理会话不能替它执行；告诉用户去那个会话里批准。
- **开发会话可以再开会话。** 被开出来的会话归属于开它的那个会话，它的结果先回到那里。管理会话想了解，就问那个开它的会话，或者直接看 Git。
- **远程遥控**：用户可以在手机上回答会话的选择题、给批准，但看不了桌面上的效果。
- **嵌套子代理**：不同版本支持的层数不同，不要让流程依赖它。
- **审查、调研子代理的定义**放在 `.claude/agents/<名字>.md`，frontmatter 写 `name`、`description`、`tools`。只读的审查者只给 `Read`、`Grep`、`Glob`。**`Bash` 不是只读工具**：它能写文件、能跑任意脚本，给了它，配置就保证不了只读。需要跑测试时，交给有权限的验证会话去跑；或者在项目的权限设置里只放行明确的几条命令，并在隔离的环境里跑。正文照 `templates.md` 里的审查者开场指令写。

## claude.ai

适合做管理会话里「想清楚」的那部分：讨论方案、写简报、评审文档。它碰不到本地仓库和 Git，所以不能核对结果，也不能合入、推送。用它做管理会话时，核对和集成交给本地会话。

## Codex

〔未验证〕本节等在实际项目里用过再补。已知只有：它读 `AGENTS.md` 作为仓库指令，所以项目档案放在 `AGENTS.md` 或由它链接。
