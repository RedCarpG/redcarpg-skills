# 模板

把 `<...>` 换成实际内容。项目档案里已经写了的（分支流程、谁合入谁推送、worktree 脚本），简报里写「按项目档案」即可，不用重抄。

## 任务简报（开开发会话时）

```text
任务：<一句话目标>
验收：<用户怎么判断做好了；能用截图或录屏的写明>
仓库与基线：<仓库>，从 <基线分支> 开 <分支名>，用 <worktree 脚本或通用方式>
写入边界：只改 <路径…>；不碰 <路径…>
共享契约：<涉及的接口、版本号、锁文件；谁是负责人；没有写「无」>
运行环境：<要不要占桌面实例、端口、数据目录；用完怎么还>
需要用户亲手做的：<登录、许可、付款、密码、下载确认…；一开始就一次问完；没有写「无」>
检查：<项目档案的快速检查>；改了共享类型或接口时跑所有消费者的测试
交付：<谁验收；谁合入（配置 A 或 B）；谁推送>；交接写在 <任务文档 / PR / 续接文件>
背景：<给没看过这段对话的人：为什么做、已经决定了什么、不要做什么>
```

## 结束报告

```text
<仓库>/<分支> @ <提交>｜<已合入 / 已推送 / 都没有>｜<在等谁、等什么；没有就写下一步>

做了什么：<可见行为或可定位的改动>
验证：
- <检查或步骤>：PASS / FAIL / 未运行 / 不适用（<环境>，<受检提交>）
- …
没做的、风险：<…>
还开着的：<没删的 worktree、在跑的服务和端口、占用的桌面实例；没有写「无」>
```

## 持久交接（挂起、换会话、跨机器、等很久）

写在接手方能访问的一个地方。先找已有的记录，更新同一处。

```markdown
## 交接

- 任务 / 状态 / 负责：<任务入口> · <进行中 / 阻塞 / 待审阅 / 待验收 / 已合入> · <谁>
- 仓库 / 分支 / 基线 / 受检提交：<…> · <base> · <tested head>
- 已完成：<…>
- 验证：<按结束报告的格式>
- 下一步：<动作、谁做、卡在什么>
- 按需：未提交改动在哪；跨仓库依赖和合入顺序；还占着的资源；回退办法
```

交接本身要提交时，最终的 HEAD 由 Git 读取，这里只记实际受检的那个提交。

## 开场指令

### 开发会话

```text
你负责 <任务入口>。先读仓库指令文件（含项目档案）和任务入口，以及它依赖的契约。
只改写入边界内的文件；要动共享契约或版本号，先停下来说明。
需要用户亲手做的步骤，开始时一次列出来问。
做完：跑项目档案的快速检查和相关测试，拿验收证据，按项目档案找验收人、合入或提 PR；交付的提交和证据都能找到之后再清理 worktree。
最后的结束报告第一句写：仓库/分支 @ 提交｜合入推送状态｜在等谁等什么。
```

### 换会话接手

对旧会话：

```text
把进度写进 <任务入口> 的交接小节：已完成、进行中、下一步、已知问题、受检提交、还开着的东西。然后提交。
```

对新会话：

```text
继续 <任务入口>。先读仓库指令文件、任务入口和交接小节，再看 git status、worktree 列表和分支差异。
交接和 Git 不一致时以 Git 为准，并告诉我差在哪。然后接着做。
```

### 审查者（子代理或一次性新会话）

```text
审查 <分支或 PR>，任务入口是 <…>。对照验收条件、写入边界、项目档案的规则和相关契约逐项检查。在你现有的工具权限内能跑的检查才实际跑；跑不了的写进「未能验证」，交给有权限的验证会话。
只报问题，不改代码。按「结论 / 必须修复 / 建议改进 / 未能验证」输出，每条注明文件和位置。
```

### 管理会话：同步进度

```text
同步进度：看所有开发分支、worktree、PR 和 CI 的状态，以及各会话最近的结束报告。
先用 Git 核对报告里说的合入和推送；列出：等用户的事、可以推送的、卡住的、下一步该派的任务。
```

### 管理会话：合入和推送

```text
<分支或 PR> 已经验收。按项目档案合入（先按档案同步远端新内容，再定合入顺序，后合入的重新核对基线）。
需要预测冲突或主目录有运行中的实例时，先在临时 worktree 里真合一次并跑检查。
推送后告诉我：推了哪些提交、CI 状态，以及还在进行中、需要同步集成分支的开发线。
```
