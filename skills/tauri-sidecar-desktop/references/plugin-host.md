# 插件宿主

适用：应用把「针对某个软件、某个服务的功能」做成插件，主线只留接口；插件放在另一个仓库，和 sidecar 同一个进程运行（`import()`）。这套做法在一个桌宠上从接口 1.0 加到 1.12，搬出去 9 个插件，每一步都经用户验收。权限的细节（打开时确认什么、工具怎么问）偏安全，另见 ai-assistant-tool-safety 那个 skill，这里只摘要。

## 1. 接口：一个纯 TS 文件，插件仓库复制它

- 接口的类型和版本号放在主线一个纯 TS 文件里（例如 `sidecar/src/shared/plugin-api.ts`，`export const PLUGIN_API = "1.0"`），不引别的。
- 插件仓库用脚本（`scripts/sync-api.mjs`）从本机主线复制这一个文件。插件仓库的 CI 从主线对应标签取来比，不一样就红。不发 npm 包：就一个文件，发包只是多一道手续。主线是私有仓库时，CI 要一个只读 Contents 的 token；没设就只警告。
- **版本：** 加东西升小版本，改了、删了已有的升大版本（旧的大版本留一阵）。插件清单写 `"api": "1.2"`，意思是「要 1.x、至少 1.2」：

| 宿主 | 结果 |
|---|---|
| 1.3 | 加载 |
| 1.1 | 不加载，提示「要新一点的宿主」 |
| 2.0 | 不加载，提示「这个插件要更新」 |

- 主线测试里放一张「接口表」：接口文件里每一项对应主线的实现，改了接口没升版本就红。
- 第一版只做插件真要用的几样（工具、通知来源、一栏设置、凭据、数据文件夹、定时、日志、问用户），别的等到第一个要用它的插件那一步再加，每次升小版本。

## 2. 加载

- 启动时只读每个插件的 `plugin.json`，不加载代码。默认关着，用户在界面里打开了才 `import()`、调 `activate(host)`。开关和同意过的权限存在一个数据文件里。
- 开、关马上生效，不用重启；改了插件代码点「重新加载」（关掉再开）。开发时插件仓库的 `npm run dev` 编完，经本机端口（带 token）通知宿主重新加载这一个。
- 一个插件出错不连累别的：`activate`、工具、定时器抛错都接住，记日志，标成「出错了」，别的照常。
- 插件找两个地方：数据目录的 `plugins\<id>\`，加上开发文件夹（本机配置或环境变量，用 `;` 隔开）。同一个 id 两边都有，开发文件夹优先，界面上写「（开发版）」。插件的数据一律在 `plugin-data\<id>\`，不管代码在哪。
- 插件的依赖用 esbuild 打进一个 `index.mjs`，装插件不用 `npm install`。
- 插件不能带原生依赖（`.node`）和 Rust：要新的系统能力，先在主线加一个通用命令，再给接口加一项。大的、有自己依赖的（比如一个机器人程序），由插件自己起子进程。
- 主线自带一个最小的示例插件（不针对任何服务），进程级测试用它查：找到、打开、它那一栏的按钮、通知、重启还开着、关掉那一栏空了、出错标出来、太新的不加载、权限变了不自动开。

## 3. 关掉时全部收回

- 每个插件拿到一个只属于它的 host 对象（例如 `scope.ts` 里建的）。工具、通知来源、设置栏、定时器、本机端口路由、窗口、事件监听都经它登记。
- 关掉插件时，这个对象登记过的全部收回，不靠插件自己写清理代码。
- 插件的工具变了（开、关），换一个新的聊天会话，模型面前的工具列表才会变。

## 4. 把内置功能搬成插件

在主线删掉旧代码的**同一个提交**里加搬家：

- **开关跟过去：** 一张 `retired` 表列出搬走的功能，以及怎么看出用户以前在用。以前在用、又找得到同名插件的，替用户打开**一次**，记下已经开过，以后不再管。
- **坑：读存着的值，不要读「现在生效的值」。** 搬行情功能时，先用了 `switches.on("market")`。模块拿掉以后它总回默认值「开」，用户关过的也被当成在用，被自动打开了。改成读存下的值（`saved(id)`）；没存过的，再看旧配置的默认值。
- **数据跟过去：** 清单里 `migrate.files` 列的文件，从数据目录复制进插件的数据文件夹：先复制再改名，不覆盖，旧的留着当备份，留记号。
- **旧地址照旧能用：** 别的程序已经装好的 hook 地址不变，主线把旧路径转给插件（`migrate.routes`），不用用户重新装。
- **凭据不用动：** 名字一开始就按 `功能名.xxx` 起，搬成插件后正好是 `插件id.xxx`。
- **找不到插件**（别人的电脑、正式版）：提示一声「某某已经改成插件了，去哪里装」，不悄悄消失。
- **卸载：** 插件可以声明一个卸载脚本，安装包的卸载程序用安装目录里的 node 挨个跑，每个最多 20 秒、出错不影响下一个、都以 0 退出、不拦着卸载；自动更新时不跑。插件用它收起装在别处的东西（比如装进别的工具设置里的 hook），在自己的数据文件夹留条子，下次装上、打开时再装回去。（这一条的真机验收还没做完。）
- 每搬一个，合进主线前从分支起一次，让用户确认功能、设置、数据都和搬之前一样。

## 5. 权限摘要

- 同一个进程，清单里的权限是**说明**，不是隔离。对用户说实话。
- 打开前把权限写成给人看的几行（联网到哪、起什么程序、改哪些外部文件、开端口、会不会以角色身份在别处发消息、要哪些账号），打开时再问一次。
- 给权限算指纹，新版本多要了权限先不加载，等用户同意。
- 不是只读的工具每次问；凭据只能拿 `插件id.xxx`；端口只给 127.0.0.1；问用户只能通过宿主的 `confirm`。
- 有服务条款风险的插件只能手动装，不进官方列表、不进发布版；主线代码和文档里不出现具体服务的名字。
