# 项目档案

每个项目一份，放在仓库指令文件（`CLAUDE.md`、`AGENTS.md`）里，或者由它链接。会话开工前读它；本 skill 只补档案没写的。

## 要回答的问题

| 问题 | 写什么 |
|---|---|
| 仓库 | 有几个仓库，彼此的依赖；跨仓库的契约放在哪、副本怎么标来源 |
| 分支流程 | 功能分支从哪开、合到哪；集成分支、发布分支；merge 还是 rebase；分支命名 |
| 谁验收、谁合入、谁推送 | 验收人是谁（用户、审查者、PR 审批）；选配置 A（集成者合入）或 B（开发会话合入、管理会话推送）；哪些动作每次都要用户明确同意 |
| worktree | 开和删用什么脚本；哪些不进 git 的东西要接进来（依赖目录、模型、本机配置）；删之前要先处理什么；什么时候才能删（例如提交已在集成分支或远端 PR 上） |
| 只有一份的资源 | 桌面实例、开发端口、数据目录、共享依赖目录、缓存、构建产物、测试设备；默认谁占用 |
| 快速检查 | 每次改代码都跑的命令（项目有 lint、类型检查等静态检查时包含它们）；改共享契约时要加跑哪些 |
| 验收分档 | 哪些改动可以截图或录屏验收、用什么工具；哪些必须真机；发布前查什么 |
| CI 和门禁 | 跑在哪些机器上；合并前必须通过哪些检查（草稿、普通 PR、发布 PR 分别是什么）；谁、什么时候触发完整检查；CI 不可用时是等恢复，还是走事先定好的替代流程 |
| 云端会话 | 每任务一条分支各开 PR，还是推到常驻分支攒常开 PR；常开 PR 是否开成草稿；开始前要同步什么 |
| 只有用户能做的事 | 登录、授权、付款、密钥、下载安装、真机操作 |
| 记录放哪 | 任务文档在哪、进度怎么看、交接写哪、经验写哪 |

## 例子（Cirra，2026-11，摘要）

- **仓库**：cirra-deskpet（桌面应用主线）、cirra-plugins（插件，复制主线的插件 API，`api/SOURCE.json` 记来源提交和版本）、cirra-voice（语音服务）。插件 API 版本号由主线负责，插件声明最低版本。
- **分支流程**：功能分支从本地 `DEV` 开 → 用户验收后 `merge --no-ff` 进本地 `DEV` → 管理会话推 `DEV`（同时更新 `STAGING`）→ PR `DEV → main`，CI 通过才合。不用 rebase。
- **配置 B**：开发会话合入本地 `DEV`；推送、开 PR 只由管理会话做。合并、推送、删远端分支每次都要用户明确同意。
- **worktree**：`scripts/new-worktree.ps1 <名字> -Branch <类型>/<名字>`，用目录联接接入 `node_modules`、模型、扩展包源文件和 Rust 编译目录；删用 `remove-worktree.ps1`，它先拆联接（否则会删到主目录里的东西）。不要在 worktree 里 `npm install`，会把联接换成真目录。
- **只有一份的资源**：同时只能开一个应用实例（开发端口只有一个），日常实例在主目录跑开发服务器、会热更新；应用数据目录各 worktree 共用。别的会话开着实例时不要替它关。
- **快速检查**：代码改动跑 lint、类型检查和相关测试；改了共享类型或接口，跑所有用到它的测试；完整一套交给 CI。
- **验收分档**：设置页、布局、动画、角色动作用无头浏览器加假宿主截图或录 GIF；系统窗口行为、托盘、声音、真实账号登录、插件真加载要真机。
- **CI**：通用检查在 Linux，Windows 只跑和路径有关的测试、打包和 Rust；直接推送只有 `main` 跑，开发分支靠 PR 查；进 `DEV` 的草稿 PR 不跑。
- **云端会话**：推到常驻的 `DEV-cloud`，常开草稿 PR `DEV-cloud → DEV`，开始前先把 `DEV` 合进来；合这个 PR 用 merge commit，不 squash。
- **记录**：设计和验收清单在 `docs/<功能>.md`，进度由 `npm run docs:status` 现算；跨项目经验在用户的经验库；项目里不在代码中的约定在项目记忆。
