# Live2D（Cubism）

渲染库：`untitled-pixi-live2d-engine` 1.4.0（PixiJS 8，Cubism 2–5，不用 eval）。别的 pixi-live2d 系渲染库结构相近，但引擎内部的细节要对着自己的版本确认。

## 加载和读写参数

1. **加载顺序：Cubism Core → 注册 render pipe 的模块 → PixiJS `Application` → 模型。** 渲染库一被 import 就找 `window.Live2DCubismCore`；PixiJS 8 在 `app.init()` 时建好渲染管线，plugin 注册晚了就画不出来。先动态插入 Core 的 `<script>`，再 `import` 模块，最后 `init`。Core 里有 WASM，CSP 加 `'wasm-unsafe-eval'` 就够。示例模型 Hiyori 加载约 256 ms。
2. **写参数先用 `getIdSafe(name)` 换成句柄。** 直接把字符串传给 `addParameterValueById`，只对少数已注册的参数有效，其余会读写到别的参数上。
3. **引擎一帧的顺序：** 动作 → saveParameters → 表情 → 眨眼 → 物理 → Pose → beforeModelUpdate → 模型计算 → loadParameters。
   - 在 `beforeModelUpdate` 里加的值每帧还原，不会越加越多；但进不了物理。
   - **程序叠加（表情叠加、待机晃动、跟音乐）都包住 `physics.evaluate`，在它之前加。** 用户反馈过「跟着音乐只有头在晃」，就是因为加在了物理之后。
   - 要读「真正画上去的值」，在 `beforeModelUpdate` 里读。
4. **头、身体角度是物理输出的模型（VTube Studio 模型常见）。** 这些模型把 `ParamAngle*`、`ParamBodyAngle*` 交给物理算，真正带动的是 `AngleX`、`PositionX` 这类输入。实测点头时 `ParamAngleY` 物理前变了 16°，物理后是 0。
   - 读 `physics3.json`：输出权重 ≥ 50 的参数算被盖掉；改写到这组物理里权重最大的输入，方向按 `Reflect`；这个输入本身也是输出就继续往上找；输入是头角度的，身体那项不用写。
   - 倍数 = 1 / (归一化上限 ÷ 输入参数上限 × π/180 × Scale × 输入权重)。实测输入 -20 时输出 -21.3，公式算是 1.067 倍，对得上。

## 给 VTube Studio 模型补齐

5. **`model3.json` 常常不全：** 表情、动作在 `*.vtube.json` 的快捷键里，`EyeBlink`、`LipSync` 组是空的，不补就不眨眼。在旁边另写一份自己的 `model3.json` 补上（`EyeBlink = ParamEyeLOpen / ParamEyeROpen`、`LipSync`、`Expressions`、`Motions`），原文件不改。
6. **没有像样的 Idle：** 这类模型平时靠摄像头带动，Idle 常常没有，或者只有汗滴、闪光。读 Idle 写了哪些参数，带不动头和身体就用程序待机：
   - 头、身体三个慢正弦 + 呼吸，只写标准参数，物理会跟着动；
   - 每个方向再叠一个不成整数倍的更慢正弦，每次启动相位随机，看着不重复；
   - 闲着时每 12–25 秒眼睛瞟一下别处，约 1 秒后回来。
7. **贴图常是 8192：** 一个模型显存几百 MB 到 1.5 GB。另存一份缩到 2048 的。
8. **包围盒被特效带偏：** 按所有 drawable 算的包围盒，会把平时透明的特效算进去（官方示例 Mao 的魔法特效让包围盒有身高的 2.4 倍）。只算不透明度 > 0 的图形；水平对准模型原点（身体中线）；点击范围取身体较窄的一边。
9. **张嘴参数不一定叫 `ParamMouthOpenY`**（Mao 用 `ParamA`）。从 `LipSync` 组读。`ParamMouthForm` 没有通用替代，缺了就跳过。
10. **头的位置不能按身高估：** 加载时动一下眨眼、张嘴参数，看哪里的顶点在变，找到眼睛和嘴；头中心在两眼偏上，大小按两眼间距算，不小于全身高的 8.5%。试过「转头时哪里在动」，不行：有的模型转头时胸口也动。

## 动作

11. **一次性动作：** 官方示例的 motion3 都标着 `Loop: true`，被戳时用 `loop: false` 播。引擎的 `onFinish` 只在动作带声音时才调用，改用动作管理器的 `motionFinish`，再加 12 秒保底（有动作 9 秒多）。
12. **换动作时上一个动作的参数会留着：** 引擎不会把上一个动作动过、新动作不管的参数拉回去（道具手一直留到下一个动作结束）。换动作、动作结束、切状态时，把这些剩下的参数每帧拉回默认，约 0.1 秒收完。（原项目已实现，验收清单这一项还没勾。）
13. **循环小动画走并行通道：** 眼泪、zzz 放在 `parallelMotionManager`，被戳的动作照常走主通道，两边不互相打断；「参数退回默认」要等两条通道都空了才做。
    - **坑：** 引擎先算主通道、再算并行通道，两边动同一个参数时，循环会盖掉播一次的动作。改法是播一次的动作在播时，每帧先算循环、再算它。（修法还没勾验收。）
    - 试过「播的时候停掉循环」，不行：循环文件还在加载时停不住。
14. **定住模型（截图、调参用）：**
    - `stopAllMotions` 不够：引擎发现没动作在播会自己再播 Idle（`shouldRequestIdleMotion`）。把 `motionManager.groups.idle` 指到一个不存在的组，取消时放回去。
    - 停掉 `internalModel.breath`，不然头发物理一直动；定住后物理还要几秒才静下来。
    - 要关物理时，不能把 `physics` 设成空（包在里面的叠加也没了），在包装里加开关跳过 `evaluate`。
15. **同一页面里多建一个模型，原来那个就不重画了**（参数照常在算），打开时还会卡。截缩略图只用舞台上这一个模型：依次换表情、定住、关物理再截。单独开窗口加载一份模型，WebView2 内存多 270–330 MB。
16. **程序做的身体层（用户看过、改过）：**
    - **说话：** 嘴开合的快、慢两条平滑线相减，得到音节，头跟着点一下；停止说话约 0.3 秒后收掉。
    - **被拖：** 弹簧（ω 9，阻尼 0.45）追「被甩到哪边」，身体反向歪、慢一拍，松手晃两下才停。
    - **一次性动作在播时：** 头和身体这层逐渐让开，眼睛不让。
    - **跟音乐点头：** 直接推速度会一顿一顿，改成给一个慢慢衰减的目标，用临界阻尼去追。
17. **通用动作库只用标准参数：** 手势类参数多半是切换式的，模型本身没有抬手的过渡，关键帧只能淡入淡出，做不出连贯的挥手。通用动作只用头、身体、眼睛、呼吸、嘴；头发交给物理。
    - 幅度按「范围的几成」写（-1 到 1，0 是默认值），加载时按每个模型的最小、最大、默认值换算并截断。
    - 缺参数时借：没有头角度就用身体角度的一半；没有 `EyeSmile` 就把 `EyeOpen` 往下合一点。主参数借完还是没有的动作就不收。

## 表情

18. **小尺寸下表情文件只改一小块（爱心眼、眼泪）基本看不出来。** 每个情绪再叠一层参数（眯眼、脸红、歪头、嘴角），和表情文件一起生效。
19. **表情文件里没写淡入淡出时，引擎默认 1 秒**，点了半天才看出来。没写的改成 0.12 秒，写了的照文件。（原项目已实现，验收清单这一项还没勾。）
20. **把滑杆调出的值存成标准 exp3：**
    - 默认值为 0 的参数用 `Blend: "Add"`，值 = 目标 − 默认；默认值不为 0 的（眼睛开合）用 `"Multiply"`，值 = 目标 ÷ 默认。
    - 运行时加表情，要同时往 `settings.expressions` 和 `expressionManager.definitions` 各加一条（后者是筛过的副本）。
    - `setExpression` 遇到同名表情直接返回，要先清掉再设。
    - 新文件加进 `FileReferences`（写完整地址），再 `Live2DModel.from({...json, url})`，试过可行。
21. **表情和动作抢同一个非标准参数（道具手）时会同时出现两只手。** 动作开始时，和当前表情有共用参数的，表情先让开，动作播完再回来。判断时排除 Cubism 标准参数（`ParamAngle*`、`Body*`、`Eye*`、`Brow*`、`Mouth*`、`Cheek`、`Breath`、`Hair*`），否则眯眼这类表情会老是消失。参数不重合但其实互斥的，手写分组。（原项目已实现，调试面板里看到「让开」生效了，完整验收还没勾。）
    - **VTube Studio 模型要多排除两类**（2026-11-11）：物理里带动标准参数的输入（`AngleX`、`PositionX`、`LeanInput`：头、身体是物理算的，表情、动作写的是它们）；不带 `Param` 的脸部参数（`EyeSmile`、`BrowInnerUp`、`MouthSmile_L`、`REyeSquint`、`CheeckPuff`）。不排除的话，带一点歪头的脸部表情一碰点头就让开、看不到。只带动手、道具的物理输入（`Movement1 → Param35`）照旧算冲突。
22. **分开「衣服、道具」和「表情」：** VTube Studio 模型的表情文件里两者在文件层面分不开（几乎全是 `Param71`、`key3` 这类自命名参数的 0/1 开关，Blend 都是 Add）。
    - 在 Node 里用 `vm.runInThisContext` 加载 Cubism Core，不渲染，拨参数、`update()`，比较哪些网格出现、消失、变形，有多少落在「脸的范围」里（拨眼、眉、嘴、脸颊参数量出来）。
    - 再结合名字（中文看最后一个词）。位置和名字缺一不可：「血」的变化 100% 在脸上，只看位置会误判成表情；单字「光」会把「高光消失」误判，改成「辉光、发光、灯」。
    - cdi3 显示名可能是噪音（有个模型 207 个参数都是同一句声明），同一个显示名出现在 ≥ 3 个参数上就不用。
    - 结果：83 个表情，人看下来错 1 个，改词表后修好。

## 其他

23. **Live2D 的渲染管线不支持 PixiJS 遮罩**，半身像只能靠窗口边缘裁掉。
24. **按像素做点击区域：** 角色和别的东西画在同一块画布上时，每 250 ms 把角色单独渲染一份 1/4 大小读透明度，拆成 8 像素一行的小矩形。头发、胳膊之间的空白点得穿。
