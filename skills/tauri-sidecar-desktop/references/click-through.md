# 透明窗口的鼠标穿透

目标：透明的地方点击落到下面的窗口，角色、气泡、按钮上照常能点。

## 为什么不能只靠前端

Tauri 的 `set_ignore_cursor_events(true)` 管整个窗口。打开以后窗口收不到**任何**鼠标事件，前端没法知道鼠标又回到了角色身上，也就没法自己关掉穿透。

## 做法：前端报区域，Rust 轮询光标

1. 前端算出「可交互区域」：矩形、椭圆，单位是 CSS 像素，原点在窗口左上角。区域变了才发命令 `set_hit_regions` 给 Rust。
2. Rust 起一个线程，约每 33 ms（每秒 30 次）读全局光标位置，换算成窗口内的 CSS 像素（`(光标 - 窗口内容区左上角) / 缩放`），落在任一区域里就关穿透，否则开。只在状态变了时才调 `set_ignore_cursor_events`。
3. 轮询线程不去问主线程：窗口位置、缩放、是否可见存一份，由窗口的 `Moved`、`ScaleFactorChanged` 事件更新；每 15 拍（约半秒）再主动读一次，防止漏事件。Windows 上光标位置直接调 `GetCursorPos`。
4. 前端报区域之前，整个窗口是穿透的。

代码：`code/click-through.rs`（Rust，核心部分）。

## 人形角色：按画出来的像素算

头发、胳膊之间、两腿之间的空隙也该点得穿。椭圆做不到。

- 每 250 ms 读一次角色的透明度，切成 8×8 逻辑像素的格子，格子里有一点 alpha > 25 就算实心；同一行连着的实心格合成一段，上下相邻、左右一样的段再合成一个矩形，少发一点。
- 角色和别的东西（比如音乐柱子）画在同一块画布上时，不能读整块：把角色**单独**渲染一份 1/4 大小去读。
- 和上次一样就不发。还没算出来、算出错时退回椭圆。
- 实测（Live2D 半身像、VRM 全身）：空隙点得穿，身上照常有反应，动作、换表情时范围跟着变。

代码：`code/hit-mask.ts`（`maskRects` 把一张 alpha 图变成矩形列表；`PixelMask` 从 WebGL 读）。

## 调试

- 调试面板放在**单独的小窗**里，不要放进透明窗口：放进去会撑大可交互区域，改变了要测的东西。
- 面板上同时显示「页面算的区域」和「Rust 手里那份」（加一个只读命令返回 Rust 的区域、现在穿不穿、光标位置），两份不一样就标红。
- 再加一个「在她身上画框」的开关，把算出来的矩形画出来。
- 窗口尺寸也显示两份：Rust 量到的大小 ÷ 缩放，和应该有的大小，差超过 1 px 标红。「换缩放后窗口大小不对」这类问题靠它一眼看出来。

## 相关的坑

- 弹层（输入框、轮盘、菜单）打开时要把它的范围加进可交互区域，不然鼠标会穿过去。
- 拖动、飘动时也要跟得上：区域按角色当前位置算，别缓存旧位置。
- Live2D 的渲染管线不支持 PixiJS 遮罩，半身像只能靠窗口边缘裁掉。
