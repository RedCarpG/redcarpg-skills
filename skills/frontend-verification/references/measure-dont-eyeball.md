# 要量的别靠看：对比度、按钮宽度、拖动区、改前改后

2026-11-24 收进，来自 lessons 里 11-22 到 11-24 的几条（棋枰、方寸远征的走查）。截图上「看着没事」的，下面这些常常量一下就有问题。

## 自动量文字对比度

脚本量网页（含 canvas）文字对比度时，误报主要来自五处：

1. **背景别猜。** 按「祖先的底色」或「画布字框里的像素」猜，深色主题、纸纹底、透明画布都会猜错。多截一张不存盘的 CSS 像素整窗口图，取**字框外一圈像素的亮度中位数**；DOM 字只在最近一个不透明底色的祖先范围内取（不然贴边的字会取到卡片外面）。
2. **前景两种算法取高的。** 只按声明的颜色算，带描边、阴影的字（伤害数字）会被判看不清；再按字框里实际像素的第 90 百分位算一遍，两者取高的。
3. **半透明也算盖住。** 底色不透明度 ≥ 0.6 或带 `backdrop-filter` 的层也算盖住，用 `elementsFromPoint` 查字中心。
4. **有意做虚的跳过，但要报数。** 自己或祖先带 `filter: blur()` 就跳过，汇总里写跳过了多少。
5. **被 `overflow` 裁掉的字只算看得见的那截**，不然会和旁边的字「交叠」。禁用的控件（`:disabled`、`aria-disabled`）不算对比度不足，WCAG 也这么规定。

实测：27 张验收图第一版报 170 条对比度、52 条交叠、27 张量不了，几乎全是这五种误报；改完剩 10 条、7 条、0 张，看图全是真的。每改一条规则，拿一页「每种毛病各埋一处、外加一页干净的」测试页回归，并临时把某条检查改坏，确认测试真的会失败。

另外两点：

- **取一圈背景会漏掉贴着字的薄晕。** 别靠加淡晕过检查（加重了又像贴纸）。字压在明暗会变的底上（灯下亮、边上暗）时，采样字底下的实际亮度挑字色：亮用深墨、暗用浅色，再垫一圈淡晕。
- **弱化色别再叠 `opacity`。** `--muted` 本身半透明（alpha 约 0.6），再加 `opacity: 0.7`，对比度从约 4.5:1 掉到约 2.6:1。要淡只用那个 token；测试里把 token 叠到背景（渐变两头、面板色）上算 WCAG 对比度，每份主题、深浅色都算。

## 往页面里装记录脚本（拦 fillText、drawImage）

- **记录按「内容 + 取整后的位置」去重，用 Map，不要数组追加。** 每帧整块 `drawImage` 的画法会让数组版每帧复制几千条，页面一慢，`waitForFunction` 就超时（实测 12 秒的场面装上后 30 秒超时，改 Map 后 10 秒）。每帧触发的钩子，记录量只能跟屏幕上不同的东西有关，不能跟帧数有关。装上后挑最重的场面比一比装和不装的耗时；只在装了时超时，先查钩子。
- **拦 `clearRect` / `fillRect` 删「被盖住的字」时，按矩形 ∩ 当前 clip 算。** 局部重画（`rect` + `clip` 到变了的格子再重放）里，整屏 `fillRect` 只涂 clip 里的像素；当成整屏涂掉会把字记录全删了，没变的格子又不会重放（实测量出 0–2 串，实际 14–15 串）。跟着 `save` / `restore` / `beginPath` / `rect` / `clip` 记每个 context 的 clip 矩形；路径里有别的形状或用了 `Path2D` 就记成「不知道」，那时一条都不删。

## 等分的按钮组、窗口拖动区

- **等分按钮：** `flex: 1` 三等分的按钮里，最长的中文标签可能正好等于按钮内宽，无头截图里没事，换个引擎（WebView2）的字体度量就折行。页面脚本比 `Range.getBoundingClientRect().width` 和按钮的 `clientWidth`，跨几种窗口宽度 × 字号跑一遍。修法：按内容定宽（`flex: 1 0 auto`、两侧留白、`white-space: nowrap`），再量余量。
- **自定义标题栏的拖动区：** 把拖动区里看得见的按钮框沿横向求并集，用总宽减掉，得到「能拖的总宽」和「最长一段」，再扣掉文字得到「纯空白」；同时量各按钮的可点尺寸，检查按钮右边有没有超出窗口。宽、中、窄三档各量一次，用东西最多的那个状态。这样抓到过窄窗口里按钮被挤出窗口的 bug，看截图很容易漏。

## 改前改后的像素对比

- **「改前」用旧提交导出的拷贝跑。** 截图脚本起本机小服务器、每次现读工作区源码时，改前那次只要和改代码重叠，就混进了新代码。先 `git archive <基线提交> <目录…> | tar -x -C <仓库外目录>`，在拷贝上跑改前；或者先跑完改前再动代码。报告写清改前是哪个提交。
- **门槛别设 0。** 同一层半透明内容，直接画和「先画到离屏画布再 `drawImage` 贴回」，每个像素有几个色阶的取整差（实测 4/255）。显卡下的 WebGL 也有 1–4 级抖动（见 `gpu-and-webgl.md`）。
- 逐帧、逐像素复现动画（假时钟、固定种子、用哪个浏览器）见 `animation-capture`。
