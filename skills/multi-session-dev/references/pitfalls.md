# 实际出过的问题

每条写：发生了什么 → 为什么 → 下次怎么做。来源是 Cirra 和 ChroniQ（2026-10 至 2026-11）。

1. **共享类型改了，CI 红了两天。** 一个开发会话把设置面板的返回类型改成可能是 Promise，只跑了「相关测试」。三个旧测试因此违反 lint 规则，其中一个其实已经坏了，但被 lint 挡在前面，CI 没跑到它。→ 项目规则写的是「本地只跑必要的」，静态检查没算进去。→ **快速检查至少含 lint 和类型检查；改了共享类型或接口，跑所有消费者的测试。**

2. **回归要靠另一个会话发现。** 给膝盖加上限后，胯的倾斜被缩小了，但腰和胸还按原角度反向回正，结果上半身歪向一边。这是另一个会话在给别的模型做测试时看到的。→ 数值检查只量了改动的那几根骨头。→ **验证要包含整体的样子**（整段动作的截图或录屏），不只是改动点的数值。

3. **跨仓库的测试替身漏改。** 主线给插件宿主加了新成员，云端改了其他插件的测试替身，但另一条线新加的插件没改，到合并时编译才报错。→ 每个插件各写各的替身。→ **改了宿主接口，就搜所有替身一起改**；更好的办法是提供一个共用的替身工厂。

4. **版本号被两边同时改。** 本地把接口升到 1.13，云端在升 1.14 到 1.17。这次没撞上，是因为云端开始前先把本地的合了进来。→ **谁开始改契约，先把对方最新的合进来**；接口副本记录来源提交，合并时就能判断取哪一边。

5. **冲突预测是错的。** 用旧版 git 的 `merge-tree` 模拟合并，对用户说「会有冲突」，结果真合时很干净。→ **在临时 worktree 里真合一次。**

6. **在运行中实例的目录里合并。** 日常实例在主目录跑开发服务器，文件一变就热更新。在那里解冲突，冲突标记会被加载进正在运行的程序。→ 在 worktree 里合并、解冲突、跑检查，干净了再写入。

7. **只有用户能做的事卡在中途。** 一个评估任务做到一半，才发现要用户装 3 GB 环境、同意模型许可、登录账号；管理会话也不能替它批准。→ **简报里列出需要用户亲手做的步骤，开发会话一开始就一次问完。**

8. **桌面实例被换掉。** 一个会话为了测试开了自己分支的版本，把用户的日常实例换掉了；另一个会话回来时发现「我开的实例被关了」。→ **写明谁在占用、什么时候还**；能用截图验收的就不占用。

9. **共享依赖目录不同步。** worktree 用目录联接共用主目录的依赖；有一个依赖在主目录里一直是旧版本，新合进来的代码要新版，测试在本机一直失败。另外，在 worktree 里装依赖会把联接换成真目录。→ 合进依赖变更后，在主目录装一次（要先问用户）；不要在 worktree 里装依赖。

10. **PR 合并之后再推的提交丢了。** ChroniQ 发生过三次，只能把漏掉的 cherry-pick 到新 PR。→ 推之前先查 PR 是否已经合并；一个 PR 的工作都推完，再告诉用户可以合。

11. **子会话的报告和实际不符。** 报告写「已合入」，但提交不在集成分支上；或者报告写「没合入」，其实用户已经在那个会话里验收、合进去了。→ **管理会话告诉用户之前，先看 Git。**

12. **同一件事写在五个地方。** 报告、任务文档、共享笔记、经验库、项目记忆各写一遍。→ 按正文 §7 的表各放各的地方；共享笔记只在工作没做完时存在。

13. **一天二十多条「等你回话」。** 4 到 6 个会话同时开着，验收、选择、装环境、填密码、付款都要用户。→ **等用户的事达到约 3 件，先汇总处理，再派新任务**；转告时把「等你的」和「仅通知」分开。
