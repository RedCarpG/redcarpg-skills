# 数据文件：存在哪、怎么存、坏了怎么办、怎么搬

## 1. 存在哪

- 放系统的应用数据目录：Windows 上是 `%APPDATA%\<应用标识>\data\`（Tauri 的 `app_data_dir()`），Rust 起 sidecar 时用环境变量告诉它（例如 `APP_DATA_DIR`）。
- sidecar 里只用一个 `dataPath("名字")` 拼路径。每个文件的路径都能再用一个环境变量单独改，测试要用（见 `testing.md`）。
- 正式版装在 `Program Files`，那里写不进去：用户能改的配置（本机设置、台词覆盖）在正式版里也放数据目录；开发版可以留在源码目录。「是不是正式版」只在一处判断（例如 Rust 的 `layout.rs`：不是调试版、资源目录里有打包好的 sidecar），别的地方都问它。
- 开发时「只开基础功能」的模式用另一个应用标识（例如加 `.basic`），数据是另一份干净的，不碰真数据。

## 2. 怎么存：原子写入

`code/write-file-atomic.ts`：先写同一文件夹里的临时文件、`fsync`，再 `rename` 换掉原文件。

- **为什么：** `writeFileSync` 会先清空再写，写到一半断电或进程被结束，文件就是空的或半截的。
- **Windows：** 目标文件正被杀毒、索引、编辑器打开时 `rename` 会报 `EPERM`、`EACCES`、`EBUSY`，等几十毫秒重试几次就好。

## 3. 坏了怎么办：按三类处理

`code/json-store.ts`。所有数据文件都走它，不要每个文件各写一套读写。

| 类 | 读不出来（不是 JSON、格式不对） | 存不了 |
|---|---|---|
| **数据**（程序替用户记的、设置里改的） | 坏文件改名成 `xxx.json.bad-日期-时间` 留着，提示一声，用空的或默认的 | 提示一声；下次存成了提示自己消失 |
| **用户手改的** | 不挪走，提示哪坏了，先用空的；用户修好了下次读就好。坏着的时候设置里又改了要存：先把坏的放一边再存 | 同上 |
| **缓存** | 重新来，不打扰用户 | 只写日志 |

- **为什么：** 以前每个文件各写一套，有的把坏文件当成空的，下次一存就把原来的盖掉。日记、天气城市、模块开关都这样丢过。
- 「格式不对」也算坏，比如该是对象的地方是数组。以前这种会悄悄用默认值、再被盖掉。
- 旧格式的兼容写在 `parse` 里（比如以前是数组、现在是对象）。
- `save` 不抛错、回 true/false。存不了要让用户知道的（设置窗口要显示「没改成」），调用方 `if (!store.save(v)) throw ...`。
- 只读的配置文件（`config.json` 这类）不走它：写错了要直接报错，不要悄悄用默认值。
- 别的程序的文件（比如 `~/.claude/settings.json`）改之前另做备份。

## 4. 从旧位置搬数据

早期把数据写在源码目录（`sidecar/` 里）的项目，迟早要搬到应用数据目录。下面的做法 2026-11 搬过一次，用户的记忆、待办、对话记录都在。

- sidecar 一启动、谁都还没读数据之前，把旧地方的复制过去：
  - 先复制到旁边的临时名字，再改名，复制到一半断电不会留下半个文件；
  - 新地方已有的不覆盖；
  - 全搬完留一个记号文件（`moved-from-<旧地方>.json`：什么时候、从哪、搬了哪些），**以后不再搬**。用户在新地方删掉的东西，下次启动不会又被复制回来；
  - 有没复制成的（被别的程序占着）：提示一声，**不留记号**，下次启动接着搬没搬成的。
- **旧文件不删**，留着当备份。要回到搬之前：关掉应用，删掉新目录，再开就重新搬一次。
- **坑：git worktree。** 从 worktree 启动时，worktree 的源码目录里没有数据。如果从那里搬，会「搬了个空」并留下记号，真数据再也搬不过来。所以旧地方一律指主目录：Rust 读 worktree 的 `.git` 文件（里面写着 `gitdir: <主仓库>/.git/worktrees/<名字>`）找到主目录。
- 「打开数据文件」这类按钮：还没搬过来的那一小会儿先开旧的，不要在新地方建一个空文件把搬家挡住。
- 测试、基础模式、单独跑 sidecar 时都不搬。
- 要搬的文件列成一张表（例如 `MOVED`），新加数据文件时想一下要不要加进去。
