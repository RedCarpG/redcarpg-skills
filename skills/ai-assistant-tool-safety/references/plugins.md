# 插件的权限

适用：插件和宿主跑在同一个进程（`import()`）的应用。如果插件跑在独立进程或沙箱里，「说明不是隔离」那条可以放宽，其他照用。

## 先说实话

同一个进程里，插件能读文件、联网、起程序，清单里的权限只是**说明**，不是隔离。界面和文档都照这个写，不要让用户以为装了插件是安全的。

## 打开之前

- 默认不加载。用户在界面里打开了才 `import()`、调 `activate`。
- 打开时弹一次确认，把清单里的权限写成给人看的几行：
  - 联网：连哪些地址；
  - 起程序：起哪些（`gh`、某个机器人程序）；
  - 改应用数据目录以外的文件：哪些（比如别的工具的设置文件）；
  - 开本机端口；
  - **替她在别处说话**：会以角色身份在别的地方发消息；
  - 要哪些账号、key。
- 卡片上写来源：开发文件夹、哪个仓库哪个版本、本地文件（写「没核对过来源」）。
- 给权限算一个指纹。新版本多要了权限就先不加载，等用户看过新增的那几条、点了同意。

## 宿主能管住的地方照样管

- 插件拿到的一切都从一个只属于它的 host 对象来。关掉插件时，这个对象登记过的工具、事件、端口、定时器、窗口全部收回。
- 插件的工具：不是只读的每次都在界面里问（「插件『名字』要用 `工具名`」），插件不能把自己加进免确认名单。`readOnly` 由插件声明，所以审核插件时要看它声明只读的工具是不是真的只读。
- 凭据只能拿到 `插件id.xxx` 名下的。
- 本机端口只给 127.0.0.1。
- 插件要问用户，只能通过宿主的 `confirm`，不能自己画一个假的确认框。
- 一个插件出错（`activate`、工具、定时器抛错）不连累别的：接住、记日志、标成「出错了」。
- 固定的、只读的后台动作（比如每 2 分钟跑一次 `gh pr list`）写在权限里，打开插件就算同意，不每次问。角色主动给别人、别的群发消息：每次问。

## 发布

- 有服务条款风险的东西（非官方 API、抓别人的客户端）只做成本地插件，不进发布版、不进官方插件列表。
- 主线代码和文档里不出现具体服务的名字和做法。
